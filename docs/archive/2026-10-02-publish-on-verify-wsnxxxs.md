- 负责人：wsnxxxs ｜ 执行 AI：Claude Opus 5.5

## 本轮目标

用户要求简化管理操作、给出直观逻辑，拍板新规则：核验通过即公开到展览馆，单轮生成且无人工介入的作品自动进入盲评，管理员只处理例外；前端审核界面与后端统一。

## 改动

- site/account.js：已处理四个页签合并为「已处理」，筛选全部 / 已公开 / 不进盲评 / 已撤下 / 存疑 / 已拒绝；旧地址 #/review/verified、off、questioned、rejected 与新地址 #/review/noarena 打开对应筛选。每行一句状态和一个下一步按钮（移出盲评 / 开启盲评 / 恢复公开 / 重新核验）；「不进盲评」「已撤下」可批量开启或恢复。核验弹窗与批量核验去掉上一轮的盲评勾选，只说明通过后的去向；已验证作品不显示「通过核验」，「撤下」两面同撤。作者「我的作品」显示同一句状态。
- site/app.js：查看器「核验状态」显示盲评状态，管理员可移出 / 开启盲评、撤下；题目页侧栏对管理员显示盲评池统计与不在池中的数量链接。
- site/arena.js：关闭的题写「暂无作品 / 还差 N 个配置」，管理员可点进题目页；规则文案改为自动进入。
- site/platform.js：arenaText、setFaces 共用；已验证提示改为「已核验并公开；单轮生成且无人工介入的作品参与盲评」。

## 决策

- 通过即公开、合格自动进盲评；前端不再自行判断盲评资格，只显示后端 arena 结论。
- 查证 show_arena 只决定 Gallery 正式盲评池，Show1 站点作品列表用 show_entertainment，改默认不影响另一站点。
- 不自动迁移存量数据，已公开但不在池中的作品由管理员在「不进盲评」批量开启。
