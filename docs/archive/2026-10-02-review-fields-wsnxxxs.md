## 本轮目标

移除不保存的核验清单，默认展开作品信息，让管理员按上传时的选项完整编辑，并理顺保存信息与审核决定的关系。

## 改动

- 核验与内容审核共用 `site/work-fields.js`：标题、提示词版本、模型（可手填）、推理档位（可手填）、Harness（可手填）、服务商、生成方式、人工介入、简介及补充说明。作品信息和补充信息默认展开；删除旧清单及专用表单代码。
- 两种审核弹窗都有「只保存信息」。对比当前表单与上次保存的值，只发送实际修改；旧缺项不被默认值覆盖，管理员编辑仍沿用既有后端 meta 接口，不改变内容审核决定。模型与 Harness 切换时提交完整的新选择。
- 单件通过核验沿用上传表单的完整必填校验；批量通过同用此校验，先应用所填的统一档位与服务商再检查。缺项作品不发送审核请求，保持选中并显示原因，其他作品正常处理。
- `docs/PRODUCT.md` 同步产品行为。功能与本轮记录使用一条英文简单句本地提交，提交号见 Git 历史。

## 决策

- 移除只作提醒、不保存的勾选清单，避免将勾选误认为核验凭证。保留上传检查、作者试加载信息及审核记录入口。
- 保存信息与作决定是两种动作；只保存、内容决定和标记存疑可以保留已有资料缺项，通过核验才要求完整信息。拒绝与存疑仍须理由。
- 完整必填检查是 Gallery 的操作约束；本轮未修改后端 API 的既有校验契约，也未扩展封面或作品文件编辑。
