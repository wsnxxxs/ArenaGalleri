# 2026-10-03 · 页面切换的加载过程整理 · wsnxxxs

- 负责人：wsnxxxs ｜ 执行 AI：Claude Opus 5.5

## 本轮目标

用户觉得页面之间的加载过程不优雅、不流畅，逻辑也说不清楚。先审查原因，再分三步修改：

1. 一次切换只淡入一次，返回时恢复滚动位置。
2. 切换时旧页面保留到新页面就绪；回到看过的页面先显示上次的内容；首屏请求并行。
3. 统一页面生命周期。

## 改动

- 审查结论：没有哪一层负责「新页面准备好了」。具体表现：
  - 平台页一次切换整页重画 3～4 次，淡入跟着重放。
  - 各处加载占位不统一，高度会塌陷。
  - 返回时等不到数据就恢复滚动，实测从 972 落到 40。
  - 每次进入页面都重新请求，没有缓存。
  - 首屏先等 data.json 再等 bootstrap，bootstrap 没有超时。
  - 页面生命周期有四种写法，route 开头要手动清理 6 个全局槽位，防止旧请求覆盖新页面的机制有四套。
- 7a82988：路由只淡入一次。页面通过 `ready` 告诉路由首批数据何时画完，路由在这之后再恢复一次滚动位置。榜单补上载入占位，展厅和沙盘的载入占位带上顶栏。删掉 style.css 中失效的 `.page` 动画。
- 794f5cb：
  - 用 View Transition 取代第一步的淡入开关：旧画面保留到新页面就绪，最多 300ms，然后交叉淡入。顶栏和侧栏单独成层，同一板块内看起来不动。
  - `apiRemembered` / `recall` 按账号记住页面进入时读到的数据（个人中心、审核、榜单）。回到页面先显示上次的内容，后台刷新后有变化才重画。
  - 首屏 data.json 与 bootstrap 并行请求，bootstrap 8 秒超时。
- 未提交（第三步）：
  - 路由只保存一个 `page`，所有页面返回同样的对象（ready / fullscreen / onPlatformChange / destroy）。拆页统一走 `teardown()`。
  - 新增 `taskPage`；查看器在同一道题的作品之间切换时只调用 `update`。
  - 首页返回 destroy，清掉定时器、监听器和 IntersectionObserver。
- 文档：docs/ARCHITECTURE.md 写明页面约定、View Transition 流程、记忆读取和首屏并行；docs/DESIGN.md 改写路由切换规范。

## 决策

- 「保留顶栏 DOM」用 View Transition 在视觉上实现，不改 DOM。原因：各页面的顶栏内容都不同，要保留 DOM 就得做一个能原地更新的顶栏组件，并改所有页面的模板，收益只有焦点和菜单状态不丢。待用户决定是否需要。
- 首屏、同页重画、后台标签页和不支持 View Transition 的浏览器直接切换，不走过渡。开启「减少动态效果」时取消动画，旧画面仍保留到新页面就绪。
- 主题切换的淡入从 0.35s 统一为 0.25s。
- 页面可以继续使用 `root.on*` 事件，由路由统一清理，不要求每个页面在 destroy 里自己解绑。

## 验证

- `npm run check`：49 文件 / 0 错；`npm test`：19/19（三步各跑一次）。
- 在 author-mock（site 叠加 dist）中用 Browser 验证：
  - 接口人为延迟 400ms 时，一次切换只淡入一次。
  - 离开「我的作品」时滚动在 972，返回后仍是 972；等待期间手动滚动则不被拉回。
  - 切换时 root、topbar、sidebar 三层过渡。
  - 首屏两个请求同时发出。
  - 记住过的榜单在挂载时同步画出。
  - 首页定时器在离开后清除。
  - 查看器换作品时保留已打开的那一栏。
  - 平台状态变化时各页面按约定重画或保留。
  - 连续快速切换时停在最后一个地址。
- 不足：Browser 面板常被系统放到后台，rAF 暂停，没有做逐帧视觉验收。mock 每次请求都生成新的 joinedAt，所以个人中心在 mock 里总会刷新重画一次，真实后端不会这样。
- 未跑：`npm run build`、`CI=1 npm run check:intake` —— 原因：没改构建和数据。未测：手机宽度、浅色主题、Safari / Firefox、减少动态效果、管理员审核页（mock 账号不是管理员）、真实后端。

## 明确没做

- 顶栏和侧栏的 DOM 仍随页面重建（见决策）。
- 题库、题目页切换面板时不经过路由，仍是原地切换，未改。
- 未推送、未部署。

## 下一步建议

- 在真实后端上用手机和 Safari 目检一次切换效果，重点看侧栏在不同板块之间的过渡。
- 如果以后觉得顶栏状态丢失（菜单收起、焦点跳走）是问题，再做可原地更新的顶栏组件。
